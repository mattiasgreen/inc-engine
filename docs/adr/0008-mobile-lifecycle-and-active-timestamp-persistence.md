# Mobile Lifecycle, Active Timestamp, and Offline Progress Resumption

To guarantee that offline progression reliably advances when the web application is backgrounded on Android, loses window focus, or is resumed after prolonged suspension, the session coordinator couples lifecycle event listening with active timestamp persistence.

1. **Mobile Browser Lifecycle Suspension**: Modern mobile browsers (notably Chrome on Android) throttle or completely suspend `setInterval` timers when an application is backgrounded or another native application gains focus. Relying solely on `beforeunload` or `unload` is unreliable on mobile, as operating systems discard background processes without firing unload events. The engine binds to `visibilitychange` (`hidden`) and `pagehide` to flush full state saves, while listening to `visibilitychange` (`visible`), `pageshow`, and `focus` to trigger explicit offline progression.
2. **Active Timestamp Persistence**: Alongside full serialized save snapshots, the session coordinator maintains a lightweight **Active Timestamp** (`${storageKey}_active_time`) in `StoragePort`. This timestamp records the most recent wall-clock millisecond where the game engine actively stepped. Upon lifecycle resumption (or cold start following an operating system process termination), the engine measures elapsed time against this active timestamp.
3. **Bounded Offline Progress and Main-Thread Responsiveness**: To prevent unthrottled loop execution from causing frame drops or triggering Android ANR (Application Not Responding) dialogs after days or weeks away, offline progress is capped at a configurable 24-hour ceiling (`MAX_OFFLINE_PROGRESS_MS`). The advancement is executed via the engine core's chunked simulation logic and, when elapsed duration exceeds 5 seconds, surfaces the **OfflineReport** dialog so the player receives clear attribution of accrued Cycles, Ticks, and currency gains.
